# 显式恢复结果：隔离预演与续接协议设计

状态：**仅本地、未发布、未接入生产路由**。本轮仅授权隔离设计和可行性回归；不修改客户端，不执行真实工具，不重发旧任务，不清除生产 pending。

## 当前可运行切片

`Server.RecoveryPreviewHandler` 是可信进程内主机构造的预演适配器，不在 `Handler`、`EmbeddedHandler` 或 sub2api 管理/模型路由注册。正常请求仍走原来的 `session_turn_pending` 保护。

```text
可信原始请求/原结果审阅记录
  -> 原账号 + session + 原 Project + native request/job IDs
  -> 原客户端完整封包 SHA256 + 已审阅结果原文 SHA256
  -> 精确匹配已受理客户端历史指纹（不调用 planTurn、不归档）
  -> 复用只读 readSessionResult，一次原历史 GET
  -> 完整终态、原文/工具契约验收
  -> 现有 Chat / Responses / Messages JSON 或 SSE 输出
  -> 保留 pending/游标/LastUsed；continuation_applied=false
```

- 变更模型、工具名、工具 schema、输入历史或协议封包的请求均不能凭旧预演凭据读取工具响应。
- 拒绝保持 `upstream_declined`；额度/生成失败保持失败；处理中和等待补充不冒充成功。未知工具、未验收附件或摘要请求拒绝预演。
- 工具 call ID 根据原账号、会话、native主任务、原封包哈希和工具索引稳定生成。预演端不执行工具；工具执行需要客户端及其授权流程。
- HTTP 200/`response.completed` 在本切片中只表示**该份模型协议结果已经完整传输**，不表示原业务任务完成或工具已执行。它不能用于清除 pending。
- 预演凭据只作为可信进程内实验输入；不是可从网络传入的通用恢复令牌，不能用于放开生产调度。

## 真实未修改客户端验收边界

使用已安装 Codex app-server 二进制、临时 CODEX_HOME、空工作目录、临时会话和仅返回常量的 dynamic mock tool。没有加载真实旧会话，也没有运行 shell、文件或网络业务工具。

实验从**该次合成客户端请求**构造已受理夹具，并将保存的 mock tool 原文通过候选网关输出。这证明标准恢复结果能被未修改的 Codex 协议栈接收，不证明真实失败会话能够直接安装恢复结果。

模拟工具返回后，客户端会发出带工具结果的下一份不同封包。旧预演凭据必须拒绝它（409），pending仍保留。客户端最终失败是这道安全门的预期结果，不得写成“任务续跑成功”。

实验接口依据及生命周期字段参考 [OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)；本机二进制生成的 JSON Schema 用于核对本次实际 RPC 形状。动态工具实验不增加或更改用户正常配置。

## 下一切片的必要协议（本轮未实现）

### 1. Arm：管理员显式批准投递

必须绑定调用方 API Key 的稳定ID、原账号/session/Project、原生request/job、完整原封包/工具 schema、结果哈希和模型协议。仅账户 Cookie + session 不足以区分不同租户。禁止自动选择另一账号或根据文本相似度猜原任务。

当前旧会话存档不含完整原工具契约和所有权证明。缺少可信原封包时只允许诊断读取，不能自动投递；如需从调用记录重建，必须先只读验真。

### 2. Deliver：持久化一次投递记录

在写出可执行工具帧前，原子保存稳定 response/call IDs、结果哈希、协议及原请求身份。相同请求只能回放同一记录，不重新生成或调上游。断线/重启/并发必须保留这个投递记录。

**稳定工具ID不等于恰好执行一次。** 未修改客户端可能仍会重复执行重复投递的工具；必须验证其真实去重能力或加入明确执行回执，不能仅凭HTTP发送成功推定。

### 3. Acknowledge：核对安装/工具回执

只有可验证的客户端回执（或明确人工确认且与原投递绑定）才能以 compare-and-swap 将该pending标记为已交付。工具输出必须关联已投递call ID且归属原会话；重复/冲突/过期回执不能再次释放或推进。

对于没有工具的普通答案，客户端如何可靠确认安装仍需单独验证；TCP完成、SSE结束和服务器写成功都不是任务上下文安装凭证。

### 4. Continue：只转发新的工具输出尾部

确认交付后，以原账号/Project继续。验证保存的历史前缀和已确认的call ID，仅向上游提交新的工具输出，不重放原用户任务。不匹配时保持冲突，不通过清pending、换Project或替换正文“修复”。
